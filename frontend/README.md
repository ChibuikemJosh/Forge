# Forge

Forge is an early-stage developer environment that combines source-code
editing with a visual, node-based representation of software architecture. The
long-term goal is structured, understandable, reusable, and controllable
development — especially when AI coding assistance is involved.

Task A establishes the full-stack foundation:

- A React + TypeScript + Vite frontend with the Forge application shell.
- A minimal FastAPI backend with a health endpoint.
- A reusable frontend API client and a real backend connection-status
  indicator.
- Documentation for the architecture boundary and the project-model direction.

## Repository layout

```
├── src/        # Frontend application (React + TypeScript + Vite)
├── backend/    # FastAPI backend and tests
├── docs/       # architecture.md and project-model.md
├── .env.example
└── package.json
```

> `forge-app/` is a leftover default Vite template generated by GitHub mobile
> tooling. It is not part of the Forge application and is kept only so nothing
> is deleted without review.

## Prerequisites

- Node.js 20.19+ (or 22.12+)
- npm 10+
- Python 3.11+

## Frontend — setup and run

PowerShell:

```powershell
npm install
npm run dev
```

Bash / zsh:

```bash
npm install
npm run dev
```

Other frontend commands:

```bash
npm run build     # type-check + production build
npm run lint      # oxlint
npm run preview   # preview the production build
```

The frontend development server runs at `http://localhost:5173` by default.

## Backend — setup and run

First, create and activate a virtual environment (PowerShell):

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Bash / zsh:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Start the FastAPI development server (from `backend/`, with the virtual
environment active):

```powershell
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

The API is available at `http://127.0.0.1:8000`; docs at
`http://127.0.0.1:8000/docs`.

Run backend tests (from `backend/`, with the virtual environment active):

```bash
pytest
```

## Frontend ↔ backend configuration

The frontend reads the backend base URL from `VITE_API_BASE_URL`. Create a
`.env.local` (git-ignored) at the repository root if you need to override it;
the example lives in `.env.example`:

```bash
VITE_API_BASE_URL=http://127.0.0.1:8000
```

## Backend connection status

The application header displays the real backend connection state:

- `Checking backend` while the health request is in flight.
- `Backend connected` only after `GET /api/health` returns `status: ok`.
- `Backend unreachable` with the failure reason when the request fails.

There are no retries and no hardcoded success states — what you see is the
result of the request the UI actually made.

## Implemented in Task A

- Forge application shell (header, sidebar navigation, central workspace,
  empty-project state).
- `GET /api/health` returning `{"status": "ok", "service": "forge-api"}`.
- Automated backend test for the health endpoint.
- CORS restricted to local Vite development origins.
- Configurable backend base URL via `VITE_API_BASE_URL`.
